API reference

This page collects the public API and the low-level DEER types that are useful for custom solvers. For an end-to-end example, begin with Getting started.

Model

ParallelMCMC.DensityModel — Type
DensityModel(logdensity, grad_logdensity, dim;
             param_names=nothing, hvp=nothing,
             logdensity_batch=nothing,
             grad_logdensity_batch=nothing, hvp_batch=nothing,
             value_grad_hvp_batch=nothing)

Describe a target density and the derivatives used by ParallelMCMC's samplers.

For a vector x of length dim, logdensity(x) must return a real scalar and grad_logdensity(x) must return a vector like x. The log-density may omit its normalizing constant. Instead of a gradient function, grad_logdensity may be an ADTypes.AbstractADType backend:

model = DensityModel(logdensity, AutoForwardDiff(), dim)

Sequential MALA needs only the gradient. Parallel MALA also needs Hessian-vector products: pass a function hvp(x, v), an AD backend as hvp, or a backend to ParallelMALASampler. A backend in hvp takes precedence over the sampler's backend. If neither is given and grad_logdensity is an AD backend g, the HVP is computed with SecondOrder(forward_counterpart(g), g) from DifferentiationInterface. AD backends are prepared when sampling starts, once the element type and array type of the initial state are known.

The optional batched functions operate on independent columns:

  • logdensity_batch(X) returns one log-density per column of X.
  • grad_logdensity_batch(X) returns a matrix shaped like X.
  • hvp_batch(X, V) returns H(X[:, j]) * V[:, j] in column j.
  • value_grad_hvp_batch(X, V) returns all three as a tuple from one call, so work they share, such as X * B in a GLM, runs once per state. It must be a callable and cannot be combined with grad_logdensity_batch or hvp_batch.

All batched derivative slots require logdensity_batch. grad_logdensity_batch and hvp_batch may each be a function or an AD backend. If grad_logdensity is an AD backend and grad_logdensity_batch is omitted, the batched gradient differentiates sum(logdensity_batch(X)). This is correct only if each entry of logdensity_batch(X) depends on the matching column of X alone.

param_names controls the parameter keys in the returned FlexiChain. With the default nothing, the chain contains one vector-valued parameter named :x. See Defining models for naming, batching, and the rules for combining derivative backends.

source

Loading LogDensityProblems adds a second constructor:

ParallelMCMC.DensityModel — Method
DensityModel(ld; param_names=nothing, hvp=nothing,
             logdensity_batch=nothing, grad_logdensity_batch=nothing, hvp_batch=nothing,
             value_grad_hvp_batch=nothing)

Construct a DensityModel from any object implementing the LogDensityProblems interface.

ld must support:

  • LogDensityProblems.capabilities(ld) returning at least LogDensityProblems.LogDensityOrder{1} (i.e. gradient available).
  • LogDensityProblems.dimension(ld) -> Int
  • LogDensityProblems.logdensity(ld, x) -> logp
  • LogDensityProblems.logdensity_and_gradient(ld, x) -> (logp, grad)

The optional param_names keyword accepts a collection of parameter names that will be used for the columns of the returned FlexiChain object. If omitted, a single vector-valued parameter named :x will be chosen, unless you also pass param_names to sample(...).

hvp and the batched functions are forwarded to DensityModel. These models have no default HVP, so parallel MALA needs hvp or a sampler backend. A backend in hvp differentiates logdensity_and_gradient, so that function must be differentiable by the backend. If it is not (for example, it calls AD internally), pass an explicit DifferentiationInterface.SecondOrder, which differentiates logdensity twice instead. AutoReactant() is unsupported. Batched derivatives require a hand-written logdensity_batch.

source

See Defining models for examples and the meanings of the derivative arguments.

Samplers

ParallelMCMC.MALASampler — Type
MALASampler(epsilon; cholM=nothing)

Create a sequential Metropolis-adjusted Langevin (MALA) sampler with positive step size epsilon.

This sampler is useful as a baseline for ParallelMALASampler and for checking a model with an ordinary sequential transition. Pass cholM=cholesky(M) to precondition proposals with a positive-definite mass matrix M. With M = L * L', the proposal is y = x + epsilon * M * gradient(x) + sqrt(2epsilon) * L * noise.

The chain stores :logp and :accepted as extra fields.

source
ParallelMCMC.AdaptiveMALASampler — Type
AdaptiveMALASampler(epsilon_init; n_warmup=1000,
                    target_accept=0.574, gamma=0.05,
                    t0=10.0, kappa=0.75, cholM=nothing)

Create a sequential MALA sampler with dual-averaging step-size adaptation.

Adaptation begins at the positive step size epsilon_init, targets the acceptance probability target_accept, and stops after n_warmup warmup transitions. The averaged step size is then held fixed. Set discard_warmup=true in sample to omit warmup-marked states from the returned chain.

gamma, t0, and kappa control the dual-averaging schedule. Their defaults are usually a better starting point than manual adjustment. cholM has the same preconditioning meaning as in MALASampler.

The chain stores :logp, :accepted, :step_size, and :is_warmup as extra fields. This sampler is a convenient way to choose an epsilon for ParallelMALASampler.

source
ParallelMCMC.ParallelMALASampler — Type
ParallelMALASampler(epsilon; T=64, maxiter=200,
                    tol_abs=1e-6, tol_rel=1e-5,
                    jacobian=:stoch_diag, probes=1,
                    jacobian_damping=1, jacobian_clip=1,
                    cholM=nothing, backend=nothing)

Create a MALA sampler that solves blocks of transitions with DEER.

epsilon is the positive MALA step size. T is the number of transitions in each DEER block; it does not determine how many samples sample returns.

The nonlinear solve stops after maxiter updates, or when its largest elementwise change is at most tol_abs + tol_rel * maximum(abs, trajectory). A block that reaches maxiter is still returned as samples, and sample logs one warning for the run.

jacobian_damping and jacobian_clip replace each diagonal Jacobian estimate J with clamp(jacobian_damping * J, -jacobian_clip, jacobian_clip). This stabilises DEER for multimodal targets and large step sizes without changing the samples; see DEER.solve. The defaults (1 and 1) match the ParallelMALA sampler of the reference implementation. damping is deprecated.

jacobian=:stoch_diag estimates each transition Jacobian's diagonal with probes Hutchinson vectors. jacobian=:diag computes the exact diagonal with one Jacobian-vector product per parameter dimension.

backend is the AD backend for Hessian-vector products that the model does not provide; it is never used for the gradient. It is not needed when the DensityModel has a function hvp (and a function hvp_batch, if it has batched functions), and a backend given as the model's hvp takes precedence over it. If backend is nothing and grad_logdensity is an AD backend, the HVP is built from that backend as described in DensityModel. With backend=ADTypes.AutoReactant(), the model's grad_logdensity must be AutoReactant() or a function. cholM has the same preconditioning meaning as in MALASampler.

sample normally runs whole DEER blocks. Passing callback or initial_state switches it to the generic step-wise AbstractMCMC loop.

See Getting started for tuning advice and GPU execution for backend-specific device constraints.

source

All three implement the AbstractMCMC interface. The usual entry point is sample(model, sampler, n; kwargs...), optionally with an RNG or an AbstractMCMC ensemble such as MCMCThreads().

Transition and state types

These types are part of the AbstractMCMC protocol. Most users receive them from AbstractMCMC.step and do not construct them directly.

ParallelMCMC.MALAState — Type

State for a MALASampler chain. Holds the prepped model so AD preparation happens once per chain, and the log-density and gradient at x so each step evaluates them only at the proposal.

source
ParallelMCMC.MALATransition — Type

One MALASampler sample: parameter vector x, its log-density logp, and an accept/reject flag.

source
ParallelMCMC.AdaptiveMALAState — Type

State for an AdaptiveMALASampler chain, including dual-averaging adaptation statistics. Holds the prepped model so AD preparation happens once per chain.

source
ParallelMCMC.AdaptiveMALATransition — Type

One AdaptiveMALASampler sample: parameter vector x, its log-density logp, the step size used for that transition, and whether the sample came from warmup.

source
ParallelMCMC.ParallelMALAState — Type

State for a ParallelMALASampler chain. Holds the prepped model so AD preparation happens once per chain.

source
ParallelMCMC.ParallelMALATransition — Type

One ParallelMALASampler sample: parameter vector x and its log-density logp.

source
ParallelMCMC.MALATapeElement — Type
MALATapeElement(ξ, u)

One element of the MALA noise tape: a noise vector ξ ~ N(0,I) and a uniform scalar u ~ Uniform(0,1). Stored with a concrete vector type V for type stability inside DEER.TapedRecursion.

Device support

Loading CUDA activates the package extension for CuArray storage. Loading Reactant activates ADTypes.AutoReactant() support for derivative arguments and the parallel sampler's backend. The restrictions and backend comparison are documented in GPU execution.

ParallelMCMC.needs_host_staging — Function
needs_host_staging(x::AbstractArray) -> Bool

Whether x has to be filled on the host and copied over, rather than written element by element in place. false for anything with cheap scalar indexing, which is the default.

ReactantExt also reads it as "this array lives on a device", to warn when the XLA client is on the host while the parameters are not.

CUDAExt defines it for CuArray. To support another device array type:

ParallelMCMC.needs_host_staging(::ROCArray) = true

Low-level DEER API

ParallelMALASampler builds on the types below. Use them directly when solving a custom taped recursion or managing workspaces across repeated solves.

ParallelMCMC.DEER.TapedRecursion — Type
TapedRecursion(step_fwd, jvp, tape; fwd_and_jvp=nothing, fwd_and_jvp_batch=nothing)

Deterministic recursion driven by a pre-generated tape.

  • step_fwd(x, tape_t): exact forward transition (may include MH accept/reject).
  • jvp(x, tape_t, v): explicit JVP (x, tape_t, v) -> J·v of the differentiable surrogate step. Required; must not call AD through step_fwd's control flow.
  • fwd_and_jvp(x, tape_t, v): optional fused function -> (x_next, J·v).
  • fwd_and_jvp_batch(Xbar, Z): optional batched function -> (FT, Jt).
source
ParallelMCMC.DEER.DEERWorkspace — Type
DEERWorkspace(S_template::AbstractMatrix, s0_template::AbstractVector)
DEERWorkspace(s0_template::AbstractVector, T::Integer)

Reusable buffers for DEER updates and solves.

Matrix buffers use the array type and device of S_template; vector buffers use those of s0_template.

probe_rng is a random number generator on the device of S_template, or nothing. If it is set, the batched Hutchinson probes are drawn on the device, seeded from the caller's rng. Otherwise they are drawn on the host, and device arrays that require host staging also get CPU buffers for them.

source
ParallelMCMC.DEER.solve — Function
solve(rec::TapedRecursion, s0; init=nothing, tol_abs=1e-4, tol_rel=1e-3,
      maxiter=200, jacobian=:stoch_diag, damping=1.0, probes=1,
      rng=Random.default_rng(), return_info=false, workspace=nothing,
      copy_result=nothing, jacobian_damping=1, jacobian_clip=1, warn=true)

Run DEER until the change between iterates meets the tolerances or maxiter is reached. These defaults differ from those of ParallelMALASampler.

Set return_info=true to return (trajectory, info), where info has fields converged, iters, metric, jacobian, damping, probes, jacobian_damping, and jacobian_clip. Reaching maxiter logs a warning rather than throwing an error; pass warn=false to silence it.

Pass a DEERWorkspace to reuse buffers across solves. Otherwise, one is created.

With a supplied workspace, the result is copied by default so later solves cannot overwrite it. Set copy_result=false to skip that copy, but use or copy the result before reusing the workspace.

Two keywords stabilise the Newton step when the linearized recursion amplifies errors, which happens for multimodal targets and large step sizes (Zoltowski et al. 2025, App. B). Each diagonal Jacobian estimate J is replaced with clamp(jacobian_damping * J, -jacobian_clip, jacobian_clip) before the scan. Damping by k < 1 is the scale-ELK of Gonzalez et al. (2024). Both only change the linearization, so the fixed point is the same and the solve still finishes in at most T iterations. The defaults (1 and 1) match ParallelMALASampler: no scaling, and entries clipped to [-1, 1]. Without clipping, one-probe :stoch_diag estimates on correlated targets often exceed 1 in magnitude, and rounding error can then grow along the scan until the solve runs far past T iterations. Pass jacobian_clip=Inf to use the estimate as is.

damping is deprecated. It relaxes the iterate, S ← (1 - damping) S_old + damping S_new, which loses the T-iteration bound; use the Jacobian options instead.

source

ParallelMCMC.MALA.mala_step_surrogate_sigmoid — Function
mala_step_surrogate_sigmoid(logp, gradlogp, x, ϵ, ξ, u; cholM=nothing)

MALA step with the accept test replaced by a sigmoid, used for Jacobians.

Returns g * y + (1 - g) * x, where y is the proposal built from the noise ξ, logα is its log acceptance ratio, and g = sigmoid(logα - log(u)).

source

The in-place diagonal scan is DEER.DEERScan.solve_affine_scan_diag!. How the algorithm works explains what it computes.
